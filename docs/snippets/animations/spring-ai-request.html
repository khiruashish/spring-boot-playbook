Animated walkthroughOne ChatClient call — memory, the tool loop and RAG in advisor order

1 · Memory + RAG

  1. chat.prompt().user("Can I return fresh produce?").call() builds a ChatClientRequest, which passes through the advisors in order, lowest order first.
  2. MessageChatMemoryAdvisor loads this conversation's history from ChatMemory and adds it as messages.
  3. ToolCallingAdvisor (auto-registered) adds the schemas of the available @Tool methods. Everything after it runs inside the tool-calling loop.
  4. QuestionAnswerAdvisor searches the vector store for chunks similar to the question, filtered per tenant, and adds them as context.
  5. The augmented prompt reaches the ChatModel.
  6. The model answers in text, with no tool call, so the loop ends after one model call.
  7. On the way out, the memory advisor saves the new user message and the answer to the conversation.
  8. Your code gets the answer. Every advisor saw the request on the way in and the response on the way out, in reverse order.

2 · A tool call

  1. "Where is my order 1042?" takes the same path: history, tool schemas and policy context, then the model.
  2. The model doesn't answer. It returns a tool call: getOrderStatus({"orderId":"1042"}).
  3. ToolCallingAdvisor runs your @Tool method with those arguments plus a ToolContext: server-side data such as the customer id, which never comes from the model.
  4. The method returns {"status":"SHIPPED","eta":"2026-11-06"}, which is added to the conversation.
  5. The loop calls the model again. Because the loop runs inside the advisor chain, advisors after it (RAG, logging) run on every iteration.
  6. Now the model answers: "Your order shipped and arrives on 6 November." Per-turn limits stop runaway loops (by default 40 calls per tool and 150 in total, §9.8).
