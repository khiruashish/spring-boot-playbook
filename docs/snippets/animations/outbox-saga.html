Animated walkthroughKeeping data and events consistent — dual write, outbox + CDC, saga compensation

1 · The dual-write problem

  1. place() saves the order and the transaction commits…
  2. …then the asynchronous kafka.send() fails (broker down, timeout). The order exists, but nobody will ever hear about it: the event is lost.
  3. Flip the timing: the event is sent while the transaction is still open…
  4. …and then the commit fails. Consumers act on an order that doesn't exist: a phantom event. No ordering of the two calls fixes this; two systems can't share one atomic commit.

2 · Outbox + CDC

  1. Instead, write the order and an OrderPlaced row into the outbox table: same database, same transaction.
  2. One COMMIT makes both durable, or neither. Nothing talks to Kafka inside the transaction.
  3. PostgreSQL records the commit in its write-ahead log. Debezium reads it through a logical replication slot.
  4. Debezium's outbox event router takes the topic from aggregate_type and the key from aggregate_id, so events for one order stay in order.
  5. It publishes to grocery.order.placed.v1 and confirms its position, which lets PostgreSQL free that WAL.
  6. Consumers get the event at least once, so they must be idempotent (§2.5): an inbox table, a conditional update or an upsert.
  7. The operational catch: if the connector stops, the slot keeps every WAL segment since its last confirmation and the disk fills up. Alert on replication slot lag.

3 · Saga with compensation

  1. Checkout runs as an orchestrated saga. The coordinator persists STARTED and sends ReserveStock (through its outbox and Kafka, as in scene 2).
  2. inventory-service reserves the stock in its own local transaction and replies StockReserved. The coordinator persists STOCK_RESERVED.
  3. Next command: AuthorizePayment.
  4. The card is declined. There's no distributed rollback, because the reservation already committed in another database. The saga moves to COMPENSATING.
  5. The coordinator sends ReleaseStock, a compensating action: a semantic undo, not a rollback.
  6. Stock released, saga COMPENSATED, order CANCELLED. Every transition is persisted and idempotent; if compensation kept failing, the saga would go to STUCK for a human.
