    3. Custom Cross-Field Validator¶

    L2 ★★☆ · @Constraint, ConstraintValidator, class-level constraints, property nodes

    Problem¶

    A booking needs checkOut after checkIn and at most N nights (N configurable in the annotation), plus a known room type. Write reusable custom constraints. The cross-field error must point at the checkOut field so a UI can highlight it.

    Key idea¶

    A field-level constraint (@KnownSku) validates one value. A class-level constraint (@ValidDateRange on the record) sees the whole object, which a rule involving two fields needs. Annotation attributes (maxNights) parameterise the validator through initialize. buildConstraintViolationWithTemplate(...).addPropertyNode("checkOut") attaches the error to a specific field.

    classDiagram class BookingRequest { <<record, @ValidDateRange(maxNights=14)>> @NotNull LocalDate checkIn @NotNull LocalDate checkOut @NotNull @KnownSku String roomType @Min(1) int guests } class DateRangeValidator { +initialize(ValidDateRange) +isValid(BookingRequest, ctx) boolean } class SkuValidator BookingRequest ..> DateRangeValidator BookingRequest ..> SkuValidator

    Solution¶

    ValidDateRange.java
    package com.playbook.interview.p03;

import jakarta.validation.Constraint;
import jakarta.validation.Payload;

import java.lang.annotation.*;

/** Problem 3: a CLASS-level constraint, because "checkOut after checkIn" involves two fields. */
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = DateRangeValidator.class)
@Documented
public @interface ValidDateRange {
    String message() default "checkOut must be after checkIn and the stay at most {maxNights} nights";
    int maxNights() default 30;
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
    DateRangeValidator.java
    package com.playbook.interview.p03;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

import java.time.temporal.ChronoUnit;

public class DateRangeValidator implements ConstraintValidator<ValidDateRange, BookingRequest> {

    private int maxNights;

    @Override
    public void initialize(ValidDateRange annotation) { this.maxNights = annotation.maxNights(); }

    @Override
    public boolean isValid(BookingRequest r, ConstraintValidatorContext ctx) {
        if (r == null || r.checkIn() == null || r.checkOut() == null) return true;   // @NotNull handles nulls: single responsibility
        long nights = ChronoUnit.DAYS.between(r.checkIn(), r.checkOut());
        if (nights > 0 && nights <= maxNights) return true;
        ctx.disableDefaultConstraintViolation();                                      // attach the error to the checkOut field
        ctx.buildConstraintViolationWithTemplate(ctx.getDefaultConstraintMessageTemplate())
           .addPropertyNode("checkOut").addConstraintViolation();
        return false;
    }
}
    KnownSku.java
    package com.playbook.interview.p03;

import jakarta.validation.Constraint;
import jakarta.validation.Payload;

import java.lang.annotation.*;

@Target({ElementType.FIELD, ElementType.PARAMETER, ElementType.RECORD_COMPONENT})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = SkuValidator.class)
public @interface KnownSku {
    String message() default "unknown room type";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}
    SkuValidator.java
    package com.playbook.interview.p03;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;

import java.util.Set;

/** A field-level validator that is a Spring bean, so it could inject a repository (here: a fixed catalogue). */
public class SkuValidator implements ConstraintValidator<KnownSku, String> {
    private static final Set<String> CATALOGUE = Set.of("ROOM-STD", "ROOM-DLX", "ROOM-STE");

    @Override
    public boolean isValid(String sku, ConstraintValidatorContext ctx) { return sku == null || CATALOGUE.contains(sku); }
}
    BookingRequest.java
    package com.playbook.interview.p03;

import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotNull;

import java.time.LocalDate;

@ValidDateRange(maxNights = 14)
public record BookingRequest(@NotNull LocalDate checkIn, @NotNull LocalDate checkOut, @NotNull @KnownSku String roomType, @Min(1) int guests) { }
    BookingValidationTest.java
    package com.playbook.interview.p03;

import com.playbook.interview.support.WebTestBase;
import jakarta.validation.Validation;
import jakarta.validation.Validator;
import org.junit.jupiter.api.Test;

import java.time.LocalDate;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

class BookingValidationTest extends WebTestBase {

    private final Validator validator = Validation.buildDefaultValidatorFactory().getValidator();

    @Test
    void validator_unit_reportsCrossFieldErrorOnCheckOut() {
        var r = new BookingRequest(LocalDate.of(2025, 3, 10), LocalDate.of(2025, 3, 8), "ROOM-STD", 2);
        var violations = validator.validate(r);
        assertThat(violations).hasSize(1);
        assertThat(violations.iterator().next().getPropertyPath().toString()).isEqualTo("checkOut");
    }

    @Test
    void validator_unit_enforcesMaxNightsFromTheAnnotation() {
        var r = new BookingRequest(LocalDate.of(2025, 3, 1), LocalDate.of(2025, 3, 20), "ROOM-STD", 2);
        assertThat(validator.validate(r)).extracting(v -> v.getMessage()).containsExactly("checkOut must be after checkIn and the stay at most 14 nights");
    }

    @Test
    void validator_unit_unknownRoomType() {
        var r = new BookingRequest(LocalDate.of(2025, 3, 1), LocalDate.of(2025, 3, 3), "ROOM-XXL", 2);
        assertThat(validator.validate(r)).extracting(v -> v.getMessage()).containsExactly("unknown room type");
    }

    @Test
    void endpoint_validBooking_201() throws Exception {
        mvc.perform(post("/p03/bookings").contentType("application/json").content("""
                {"checkIn":"2025-03-01","checkOut":"2025-03-04","roomType":"ROOM-DLX","guests":2}"""))
           .andExpect(status().isCreated()).andExpect(jsonPath("$.nights").value(3));
    }

    @Test
    void endpoint_invalidRange_400() throws Exception {
        mvc.perform(post("/p03/bookings").contentType("application/json").content("""
                {"checkIn":"2025-03-04","checkOut":"2025-03-01","roomType":"ROOM-DLX","guests":2}"""))
           .andExpect(status().isBadRequest());
    }
}

    Walkthrough¶

    Code Why
    @Target(ElementType.TYPE) ... @Constraint(validatedBy = DateRangeValidator.class) A class-level constraint. message, groups and payload are required by the Bean Validation spec.
    if (r.checkIn() == null \|\| r.checkOut() == null) return true; Let @NotNull report nulls. Each constraint has one job, which avoids duplicate or confusing errors.
    ctx.disableDefaultConstraintViolation(); ... .addPropertyNode("checkOut") Moves the violation from the object to the checkOut field. The unit test asserts the property path.
    message = "... at most {maxNights} nights" Message interpolation reads annotation attributes, so the test sees "14 nights".
    @Target({FIELD, PARAMETER, RECORD_COMPONENT}) RECORD_COMPONENT lets the annotation sit on record components. It propagates to the accessor and field.

    Complexity¶

    Approach Time Space
    validate O(constraints) O(1)

    Common mistakes¶

    • Validating cross-field rules in the controller with if statements, which isn't reusable and gives inconsistent error format.
    • Returning false for null inputs in custom validators, which doubles up with @NotNull.
    • Doing database lookups in a validator on every request without caching. Validators can be Spring beans with dependencies injected, but keep them fast.

    Follow-up questions¶

    Can a ConstraintValidator use Spring beans?

    Yes. Spring's LocalValidatorFactoryBean creates validators through the application context, so constructor injection works. For example, SkuValidator could inject a RoomTypeRepository.

    What are validation groups for?

    To apply different rules in different situations (OnCreate vs OnUpdate) using @Validated(OnCreate.class). Records with separate DTOs per operation are often clearer than groups.
